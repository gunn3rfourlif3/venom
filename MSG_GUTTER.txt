Give the content column a gutter; fix page rhythm and the duplicate class bug

THE GUTTER. A pane ran from the rail's right edge to the window's right
edge with nothing either side - measured, a panel on Logistics spanned
x=208 to x=1440, with the rail ending at exactly 208. So on any page whose
top-level blocks are bordered cards (Logistics, Overview, Result slips) a
panel border sat hard against the menu and against the window.

Pages built on .panel-body looked fine only because that block draws no
border: its own padding supplied a gutter the pane never had, so the fault
was invisible precisely where there was nothing to see. That is why this
read as "those three pages are wrong" rather than as a missing rule.

The gutter belongs to the content column, not to whichever child happens
to be first, so it now sits on .pane and the children that were each
supplying their own stop doing it. Every page gets the same inset whether
its blocks are cards or not, and it holds at the narrow breakpoint where
--gut drops to 16px. The page title now lands on the same vertical line as
the card edges below it, which is the line the eye follows down a page of
panels.

An earlier attempt at this pushed each child's TEXT to the gutter instead.
That aligned the text but left the card borders flush against the menu -
it fixed the measurement I had taken rather than the thing that looked
wrong, which is why it did not help.

Two more faults fixed along the way:

NO VERTICAL RHYTHM. Pane-level blocks sat flush, spacing patched by hand
per element: measured gaps down Logistics were 0, 0, 0, 0, 16, 16, 0.
.pane-single now carries row-gap: var(--s-sect) - the scale's own name for
the space between sections - so a new section is spaced by existing.

EIGHT ELEMENTS CARRIED TWO class ATTRIBUTES, e.g.
  <div class="tiles" id="lg-tiles" class="mt-far">
The parser keeps the first and silently discards the second, so those
utilities never applied - which is where the 0s above came from. Confirmed
in the DOM before fixing. Also <main id="view-overview"> and
<main id="view-settings"> carried no class at all, so they were not panes
and missed every pane rule.

Checked across all 14 views: boxes start at 236 everywhere, no horizontal
overflow at 430px, no console errors, both themes.
